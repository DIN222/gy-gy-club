# 🏛️ GY-GY Club: Architecture Decision Record (ADR)

## 1. Философия системы (Event-Driven Architecture)
Проект **GY-GY Club** переходит от монолитного кода к **событийно-ориентированной архитектуре (EDA)**.
* **Архитектурная метафора:** Система спроектирована по принципу **Arduino**. Каждый функциональный блок — это независимый «узел» (Node) со своими входами, выходами и четким назначением.
* **Принцип разделения:** Модули не вызывают друг друга напрямую. Взаимодействие строится на подписке и публикации событий (Event Bus). Это защищает проект от «спагетти-кода» и позволяет добавлять новые зоны (комнаты, игры, бэкенд-модули) без риска сломать существующую логику.

---

## 2. Стандарты ЛЕГО-компонентов
Каждый модуль проекта обязан следовать единому контракту:
1. **Изоляция:** Вся логика, стили и разметка одного фича-сегмента инкапсулируются в отведенной директории/файле.
2. **Жизненный цикл (Контракт узла):**
   * `init()` — инициализация, привязка к DOM и подписка на события.
   * `update(data)` — реакция на изменение стейта / входящие сигналы.
   * `destroy()` — очистка памяти и отписка от событий при выходе из зоны.
3. **Единый источник правки (Single Source of Truth):** Глобальное состояние пользователя (ID, аватар, локаль, настройки) хранится в централизованном сторе (`LocalStorage` + объект состояния), а не внутри разрозненных DOM-элементов.

---

## 3. Стек технологий и Инструментарий
* **Среда разработки:** Google Project IDX (облачная IDE с поддержкой контейнеров и интеграцией инструментов разработки).
* **Контроль версий:** Git / GitHub (обязательная фиксация изменений через коммиты для исключения потери версий).
* **Интерфейс связи:** Локальная шина событий (Event Bus) на базе стандартного `CustomEvent` в JavaScript.

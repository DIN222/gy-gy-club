Проект уходит от старой концепции плоских страниц в сторону «живого» интерактивного пространства. Вместо тяжелых видео-фонов мы используем принцип точечной магии и легкого динамизма:

Производительность превыше всего: Базовый каркас, сетка и логика остаются быстрыми и легкими (чистый CSS/JS).

Атмосферные акценты (Слои динамики):

Легкие CSS/Canvas-анимации вместо тяжелых видео.

Ситуационный сканер: Многослойный звуковой фон + автоматический сбор контекста и трендов (через Google API/RSS) с генерацией смыслового юмора в реальном времени.

Реальное время: Живые ответы Мастера Юмора, привязанные ко времени суток и контексту клуба.

🏗️ Часть 2. Архитектурное решение (ADR)
1. Философия системы (Arduino-метафора)
Система спроектирована по принципу Arduino. Каждый функциональный блок — это независимый узел (Node) со своими входами, выходами и четким назначением. Модули не вызывают друг друга напрямую: взаимодействие строится на подписке и публикации событий через центральную шину (Event Bus).

2. Стандарты ЛЕГО-компонентов
Изоляция: Вся логика, стили и разметка фича-сегмента инкапсулируются в своем файле.

Жизненный цикл узла:

init() — инициализация и привязка к DOM.

update(data) — реакция на входящие сигналы.

destroy() — очистка памяти и отписка от событий.

Единый источник правки (SSoT): Глобальное состояние (ID, аватар, локаль) хранится в централизованном сторе (LocalStorage + объект состояния).

3. Стек технологий
Среда: Google Project IDX (облачная IDE).

Контроль версий: Git / GitHub.

Ядро: Нативный JavaScript (CustomEvent для шины данных).
